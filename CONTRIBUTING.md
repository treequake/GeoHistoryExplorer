# Contributing

Prefer small, well-documented improvements. Preserve provenance and disagreement.

## Contribution Expectations

- Keep Stage 0 changes architectural and documentation-focused.
- Do not introduce full application code during Stage 0.
- Preserve source claims, uncertainty, disagreement, and stated precision.
- Add or update ADRs when changing architectural boundaries or data model assumptions.
- Prefer deterministic validation and transformation steps.
- Treat AI-generated or AI-assisted outputs as downstream interpretation, not source evidence.
